# Internationalization / Internazionalizzazione

## Italiano

Family Calendar supporta attualmente **Italiano** e **Inglese**.

### Selezione lingua

Dentro Home Assistant la lingua viene letta da:

```text
hass.locale.language
```

Le locale `it-*` usano l'Italiano; tutte le altre locale usano attualmente l'Inglese come fallback.

La demo standalone fornisce intenzionalmente:

```text
it-IT
```

nel mock `hass`, così il layout italiano rimane riproducibile durante lo sviluppo e i test visuali.

### Dove vivono le stringhe

Frontend:

```text
src/i18n.ts
```

Custom integration Home Assistant:

```text
custom_components/family_calendar/strings.json
custom_components/family_calendar/translations/
```

Quando si aggiunge una nuova stringa visibile nella UI, aggiungere sempre sia la versione italiana sia quella inglese. Evitare stringhe hardcoded nei componenti quando la stessa etichetta può essere riutilizzata.

### Formattazione locale

Date e orari devono usare `Intl` / `toLocaleDateString` / `toLocaleTimeString` con locale coerente con la lingua selezionata. Stati e label specifici dei dispositivi devono essere tradotti prima di essere mostrati all'utente.

## English

Family Calendar currently supports **Italian** and **English**.

### Language selection

Inside Home Assistant the language is read from:

```text
hass.locale.language
```

Locales matching `it-*` use Italian; every other locale currently falls back to English.

The standalone demo intentionally supplies:

```text
it-IT
```

through its mock `hass` object so the Italian layout stays deterministic during visual development and testing.

### String locations

Frontend:

```text
src/i18n.ts
```

Home Assistant custom integration:

```text
custom_components/family_calendar/strings.json
custom_components/family_calendar/translations/
```

When adding user-visible UI copy, always provide both Italian and English variants. Avoid hardcoded component strings when a reusable translation key is appropriate.

### Locale formatting

Dates and times should use `Intl` / `toLocaleDateString` / `toLocaleTimeString` with a locale consistent with the selected language. Device-specific state labels should be translated before being rendered to the user.
